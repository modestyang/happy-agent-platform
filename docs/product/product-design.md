# Happy Agent Platform V1 产品设计

状态：合同冻结

日期：2026-08-05
适用入口：`/app/**` 手机端、`/admin/**` Agent 管理端

## 1. 产品目标与边界

Happy Agent Platform 是可承载多个 AI 应用的自用平台，V1 的首个应用是 AI 健身伴侣。手机端帮助用户围绕一个“当前目标”执行训练与饮食，同时持续记录不依附于任何目标的客观身体、饮食和训练事实；管理端用于配置、评测、发布和追踪实际驱动手机端 AI 花爷的 Agent。

V1 不包含支付、社交、医疗诊断、运动手表接入、任意代码型 Skill、模型生成 HTML、生产告警或自动备份。AI 只返回已登记的结构化输出，手机端以固定组件渲染。

## 2. 用户与权限边界

- 健身用户：只能访问自己的目标、偏好、计划、记录、报告和 AI 会话。
- Agent 管理员：管理组件、默认档案、Agent 草稿和版本，并查看管理域中的会话、Run、Trace 与评测。
- 手机端与管理端使用独立的外部授权边界；二者没有旧式内部服务 Token、委托换票或内部 HTTP 鉴权。
- Provider 凭据只显示掩码；明文只在写入或轮换请求中短暂出现，响应永不返回明文或密文。

## 3. 手机端信息架构

### 3.1 首页 2×2 功能块

首页固定为四个首要入口，保证单手操作和稳定心智模型：

1. 目标：当前目标摘要、剩余周期、进度和下一步。
2. 训练：今日训练、完成状态、动作数量和预计时长。
3. 饮食：今日三餐计划、记录完成度和待处理识别任务。
4. 身体：最近体重/体脂等指标、趋势和快速记录。

首页同时显示 AI 花爷入口；Agent 的结构化卡片不得改变 2×2 主导航，也不得注入任意 HTML。

### 3.2 目标

- 创建、查看历史目标、修改未完成目标并切换当前目标。
- 同一用户同一时刻最多一个当前目标。
- 目标保存类型、开始/结束日期、目标值、状态与版本号。
- 只有当前目标生成累计报告；历史目标不提供独立报告产品入口。
- 身体指标、饮食和训练记录是客观事实，不保存 `goalId`。报告读取当前目标的时间窗并聚合这些记录，切换目标不会改写历史事实。

### 3.3 训练

- 浏览训练计划列表、计划详情、每个动作的组次/时长/休息和媒体指导。
- 查看动作库并按部位、器械、难度筛选；动作详情包含步骤、注意事项、目标肌群和可访问的媒体引用。
- 在计划内替换单个动作；替换必须检查版本，避免覆盖并发修改。
- 跟练模式使用固定 UI 播放动作顺序、计时和语音提示；语音内容来自结构化字段，不执行模型生成脚本。
- 完成或手工补录训练，保存实际动作、组次、次数、负重、时长、感受和发生时间；记录独立于目标。
- 历史页可按日期游标分页查看训练记录。

### 3.4 饮食

- 系统以用户时区每天 05:30 生成当天计划，固定包含早餐、午餐、晚餐三餐；持久化任务具备状态、租约、重试次数和输入 checksum，重启后可恢复。
- 每餐展示食物、份量、热量和宏量营养素，并允许提交喜好、吃没吃、份量差异和文字反馈。
- 用户可先获取受限媒体上传票据，再创建图片识别任务；创建返回 `202` 与任务 `Location`，任务状态为 `QUEUED`、`RUNNING`、`SUCCEEDED` 或 `FAILED`。
- 识别成功只形成可编辑候选结果，不自动写入客观记录。用户确认或直接手工录入后才生成饮食记录。
- 饮食历史按日期游标分页，记录不绑定目标。

### 3.5 身体指标

- 手工记录体重、体脂率、腰围、静息心率及备注；每项允许缺省，但一次提交至少包含一个指标。
- 记录按实际测量时间排序并支持历史分页；记录不绑定目标。

### 3.6 当前目标累计报告

报告仅面向当前目标，状态机为：

- `QUEUED`：已请求，等待计算。
- `GENERATING`：正在从当前目标时间窗聚合客观记录。
- `READY`：返回截至 `computedThrough` 的训练、饮食、身体与目标进度指标。
- `STALE`：有更新记录尚未纳入，仍可展示上次完整结果并提示刷新。
- `FAILED`：最近一次生成失败，保留可重试信息，不伪造报告。

没有当前目标时返回 `404 CURRENT_GOAL_NOT_FOUND`。用户可对 `STALE` 报告发起刷新、对 `FAILED` 报告发起重试；命令异步返回 `202` 与报告资源 `Location`。报告存储目标快照和聚合结果；原始记录仍不与目标绑定。

### 3.7 偏好

偏好包含时区、单位制、饮食限制/忌口、可用器械、训练日、单次时长、语音开关和提醒设置。更新使用版本号与 `If-Match`；未填写字段不能被隐式清空。

### 3.8 AI 花爷会话

- 创建会话时冻结使用的已发布 Agent 版本，并返回创建时间和 `expiresAt`。
- 会话生命周期固定为 24 小时，从创建时间计算，后续消息不延长；到期后只读保留历史，新消息返回冲突错误并引导创建新会话。
- 发送消息异步创建 Run，返回 `202`、`Location` 和 Run 状态。
- SSE 使用递增事件 ID；客户端以 `Last-Event-ID` 重连，服务端从持久化游标续传。
- 事件类型闭合为 Run 状态、模型文本增量、结构化组件、Tool 调用、审批请求、错误和完成事件。
- 可渲染组件类型闭合，V1 包括文本、目标摘要、训练计划、动作详情、三餐计划、饮食识别候选、身体趋势、当前目标报告和确认操作；不接受任意 HTML。

## 4. Agent 管理端信息架构

### 4.1 类型化组件目录

左侧导航分别提供 Framework、Provider、Model、Tool、Skill、Hook、Memory Policy、Prompt、Output Schema 和 Evaluation Suite。所有目录支持筛选、分页、版本差异、兼容性、引用中的 Agent/Skill 和停用影响；数据库保持类型化表而非 EAV。

公共展示字段为 `componentKey`、`version`、`displayName`、`description`、`category`、`tags`、`sourceType`、`status`、`configSchema`、`schemaChecksum`、`compatibleFrameworks`、创建信息、弃用信息和替代项。生命周期闭合为 `DRAFT`、`AVAILABLE`、`DEPRECATED`、`DISABLED`、`RETIRED`。

- Framework：代码适配器登记能力、适配器版本、Skill/Hook/恢复/结构化输出支持；后台只读。
- Provider：类型、端点、工作区、凭据版本、框架支持、能力、健康状态和超时；支持凭据轮换与异步探测。
- Model：Provider 版本、模型名、模态、上下文、最大输出、Tools/流式/结构化/视觉/音频能力、默认参数与参数 Schema；支持异步能力探测。
- Tool：代码自动发现，核心契约只读；完整展示输入输出 Schema、安全上限、风险、权限、流式、幂等和构建版本。
- Skill：Markdown、元数据、只读资源和已授权 Tool；支持创建、编辑、复制、预览、差异、发布和停用影响，禁止执行任意代码。
- Hook：代码注册，核心契约只读；权限、安全、预算、Trace、审计和 Checkpoint Hook 必选，安全失败策略固定为 `FAIL_RUN`。
- Memory Policy、Prompt、Output Schema、Evaluation Suite：独立版本化，可创建新草稿版本、比较、评测引用和停用影响。

### 4.2 默认档案与继承

普通 Agent 最少只需填写名称、Framework、Provider/Model、Prompt，并选择 Tools 与 Skills。高级设置默认折叠。有效值按以下顺序解析：

`平台安全硬限制 → 框架/组件代码默认值 → 应用默认配置档案 → Agent 草稿显式覆盖`

- 平台硬限制不能覆盖。
- 草稿采用稀疏覆盖；未填写表示继承，不用含义不清的 `null`。
- 编辑器提供恢复默认值、字段来源和最终完整配置预览。
- 默认档案版本化；发布快照保存档案版本、每项来源、解析后的完整配置和组件 checksum。
- Tool Binding 只能收紧代码安全上限；写入型/高风险工具的强制审批不能关闭。

### 4.3 Agent 草稿、评测与发布

1. 创建 Agent 并编辑唯一工作草稿。
2. 解析草稿，展示默认继承和框架最终配置；不完整或不兼容时返回闭合校验错误。
3. 创建异步评测任务，使用绑定的 Evaluation Suite 运行并持久化用例结果。
4. 评测达标且安全门通过后发布；失败使用 `SAFETY_GATE_FAILED`，未知框架使用 `FRAMEWORK_NOT_SUPPORTED`，缺少外部配置使用 `DEPENDENCY_NOT_CONFIGURED`。
5. 发布生成不可变版本，冻结框架、Provider/Model、Prompt、Tool/Skill/Hook、Memory、Output Schema、Evaluation Suite、运行限制、完整有效配置和 checksum。
6. 回滚不是修改旧版本，而是从目标快照创建新的不可变发布版本。

### 4.4 会话、Run、Trace 与 Playground

- 会话页按用户标识、Agent 版本、状态和时间筛选，并展示消息与关联 Run。
- Run 页展示持久状态、预算、Token/成本、最终输出、错误和恢复游标。
- Trace 按严格序号展示模型、Tool、Hook、审批、Checkpoint 和错误事件；敏感输入按策略脱敏。
- Playground 只能针对草稿或明确版本创建隔离 Run；异步返回 `202` 与 `Location`，并通过支持 `Last-Event-ID` 的 SSE 查看事件。
- Tool 调用上下文中的 `userId`、`runId`、权限和 `operationId` 由服务端注入，模型输入不可信。

## 5. 跨端交互规则

- 写请求必须携带 `Idempotency-Key`；同一键与同一请求摘要重放原结果，不同摘要返回冲突。
- 乐观更新还必须携带 `If-Match`；缺失返回 `428`，版本不匹配返回 `412`。
- 异步创建返回 `202` 与 `Location`，查询资源状态；不得以同步超时掩盖后台工作。
- 所有错误使用 `application/problem+json`，错误码为合同中的闭合枚举。
- 日期时间为 RFC 3339，日期为 ISO 8601；计划按用户时区，服务端持久化时间点使用 UTC。
- 分页使用不透明 cursor；响应返回 `nextCursor`，没有下一页时省略该字段而非返回 `null`。

## 6. 可用性与失败体验

- 外部 Provider、百炼或 OSS 未配置时明确显示 `DEPENDENCY_NOT_CONFIGURED`，不返回伪造结果。
- 异步任务失败保留有限错误信息和可重试状态；页面可继续读取已持久化数据。
- 所有危险操作在提交前展示影响范围；强制审批、安全 Hook 与预算上限不可被 UI 绕过。
- 移动端优先保证记录与历史可用；AI 依赖不可用不阻止用户手工记录身体、训练和饮食事实。
