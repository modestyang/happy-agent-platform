# 管理后台目录与 Trace 交互优化设计

日期：2026-08-11  
范围：模型、提示词、技能、会话 Trace  
产品边界：个人应用管理后台，不扩展模型市场、组织权限或企业观测平台。

## 目标

1. 新增资源不改变列表布局，统一使用模态弹窗。
2. 表单只展示管理员真正需要填写的业务字段，统一按钮、间距和反馈。
3. 模型能力作为事实声明用于 Agent 校验，不表现为可随意改变模型能力的功能开关。
4. 提示词和技能可以不改代码、不重新发布应用地手动新增。
5. Trace 默认展示可理解的近期会话，页面不暴露用户 UUID 搜索或其他内部定位字段。

## 方案选择

### 方案 A：统一模态弹窗（采用）

模型、提示词和技能列表右上角均提供“新增”按钮，点击后打开居中模态弹窗。弹窗拥有一致的标题、说明、字段间距、取消与保存按钮；关闭后列表位置不变。

优点是新增行为一致、空间充足、不会挤压已有资源；缺点是需要新增一个可复用弹窗壳层。

### 方案 B：右侧抽屉

能保留列表上下文，但提示词模板和技能内容需要较宽编辑区域，抽屉在普通笔记本宽度下容易局促。

### 方案 C：列表内联展开

实现最少，但会继续改变页面高度和卡片位置，直接违背本轮修复目标。

## 统一弹窗与按钮

- 新增 `AdminModal`，使用 `role="dialog"`、`aria-modal="true"`、明确标题关联。
- 点击遮罩、右上角关闭按钮或按 Escape 均可关闭；保存中禁止重复关闭和提交。
- 桌面端宽度不超过 680px，移动端占视口宽度并保留安全边距。
- 底部操作区固定为右对齐：“取消”为次级描边按钮，“保存”为主按钮；高度、圆角、字体和图标尺寸一致。
- 危险操作使用克制的红色文字/描边按钮，不与主按钮混用。
- 错误保留在对应弹窗内；保存成功后关闭弹窗、更新列表并显示页面级成功提示。

## 模型页面

### 新增模型弹窗

主表单字段：

- 模型服务商
- Model Key
- 服务商 Model ID
- 显示名称
- 说明

“支持流式输出”不再展示或允许修改。当前应用统一要求 OpenAI-compatible 流式响应，创建和更新时由应用固定为 `true`。

“模型能力声明”默认收起，包含两个紧凑选择项：

- 原生支持工具调用
- 可接收图片输入

它们只描述模型官方能力，不会给模型增加功能。Agent 发布时继续根据所绑定工具和图片任务校验模型能力；不兼容时给出明确阻断原因。

### 已有模型卡片

- 卡片主体只展示名称、状态、说明、Provider 和 Model ID。
- 启用/停用移动到卡片右上角的操作菜单，不再挤在底部元数据行。
- 菜单按钮采用统一图标按钮；停用为危险操作文案，启用为普通操作。
- 不提供物理删除。

## 提示词新增

提示词列表右上角增加“新增提示词”。弹窗字段：

- Prompt Key
- 显示名称
- 说明
- 模板正文

创建后状态为使用中、revision 为 1，可立即在 Agent 编辑器中选择。Key 创建后不可修改；模板变量继续由现有 `{{variable}}` 规则自动识别。

## 技能新增

技能列表右上角增加“新增技能”。弹窗字段：

- Skill Key
- 显示名称
- 说明
- 适用时机
- 不适用时机
- 技能内容
- 依赖工具（从真实工具目录多选）

服务端校验依赖工具必须存在。创建后 revision 为 1；当依赖工具均可用时标记为运行就绪，可立即绑定 Agent。Key 创建后不可修改，不提供物理删除。

## API 与数据

- 先更新 `admin-v1.yaml` 和 coverage fixture，再实现 Java/TypeScript。
- 独立资源 API 增加：
  - `POST /api/admin/prompts`
  - `POST /api/admin/skills`
- 复用现有 `agent_prompts`、`agent_skills` 表，不新增 migration。
- 唯一 Key 冲突返回标准 `application/problem+json`，页面显示“标识已存在”。
- Provider、Model、Prompt、Skill 继续保持独立资源，不恢复聚合工作台接口。

## Trace 页面

### 信息架构

Trace 改为单一主线：近期会话 → 多轮对话 → Agent 回复下的执行过程。

- 左侧默认加载最近会话，显示标题、Agent、最后活动时间、消息数和 Run 数。
- 右侧显示所选会话；用户消息和 Agent 回复采用与调试台一致的聊天气泡与 Markdown 排版。
- 每条带 `runId` 的 Agent 回复下显示紧凑的运行摘要，并提供“查看执行过程”。展开后在原回复下展示该 Run 的模型、工具、Skill、确认、错误和耗时，不跳离对话上下文。
- 删除当前独立占据首屏的“最近运行”大卡片和强制 UUID 查询区。
- 页面不提供 UUID 输入或筛选。若后续需要搜索，只按会话标题、Agent 名称或可读用户名搜索，不要求管理员掌握内部 ID。
- 空状态只保留一个明确动作，不同时展示多个互相竞争的空卡片。

### Run 详情

独立 Run 详情仍可从调试台或会话页打开，但不再采用“指标卡 + 输入块 + 输出块 + 原始事件时间线”的技术日志布局。

- 主体首先展示一个用户消息气泡和一个 Agent 回复气泡；Agent 回复使用现有安全 Markdown 渲染。
- 状态、模型、耗时和 Token 收敛为回复气泡上方的一行轻量元数据，不再占用四张大卡片。
- Agent 回复下方默认收起“执行过程”，展开后按业务阶段分组：准备上下文、调用工具/Skill、等待确认、生成回复、结束或失败。
- 同一工具的 `STARTED` 与 `COMPLETED` 合并为一条调用卡片；`TOKEN` 原始事件不逐条展示，避免重复完整回复。
- 工具调用卡片显示可读名称、结果状态和耗时；技术标识和原始细节放在次级展开区域。
- 等待用户确认使用明确的确认状态卡；错误紧邻失败阶段展示，不使用页面内联样式。
- 会话页和独立 Run 页复用同一套对话/执行组件，避免两种 Trace 表达方式再次分叉。

### API

会话列表接口不再要求 `userId`，按 `lastMessageAt` 倒序返回近期会话。个人应用首版只需要有限数量的近期会话，不引入复杂分页、用户 UUID 搜索和分析维度。

会话详情已有消息 `runId`，前端可在展开某条 Agent 回复时按需读取现有 Run Trace；无需把全部事件塞进会话列表响应。

## 测试与验收

- 前端测试：弹窗不会挤压列表；取消/保存按钮样式类一致；流式字段不可见；能力声明默认收起；模型操作菜单位置；提示词/技能新增；Trace 默认近期会话、无 UUID 输入、对话气泡、Markdown 回复和回复下展开执行过程。
- Trace 事件归并测试：同一工具 STARTED/COMPLETED 合并；TOKEN 不重复展示；等待确认和失败阶段有明确状态。
- 服务测试：Prompt/Skill 创建、重复 Key、依赖工具不存在、revision 1。
- 集成测试：独立 API、鉴权边界和新建资源可被 Agent 草稿读取。
- 最终执行相关 Maven 测试、前端全量测试、TypeScript、ESLint、Spotless、契约 lint 和生产构建。
- 使用真实页面复核四个页面，不以接口调用代替 UI 验收。

## 明确不做

- 模型能力自动联网探测。
- 模型市场、价格和配额管理。
- Trace 指标大盘、分布式链路或日志检索平台。
- Prompt/Skill 版本市场与多人审批。
