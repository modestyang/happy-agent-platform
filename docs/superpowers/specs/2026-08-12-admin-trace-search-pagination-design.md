# Agent 管理后台 Trace 会话搜索与分页设计

## 目标

改进 Agent 管理后台的会话 Trace 页面，使管理员能够直接识别会话、按统一关键词定位会话，并在有限的页面高度内分页浏览结果。

本次范围包括：

- 展示用户名、用户 ID 和会话 ID。
- 使用一个搜索框按用户名、用户 ID 或会话 ID 搜索。
- 使用服务端分页限制会话列表高度。

AI 回复的一键复制不在本次范围内。

## 架构边界

`agent` schema 继续只保存 `user_id`，不复制用户名。用户名仍由 Fitness 模块拥有。禁止新增跨 schema JOIN、外键或事务。

Starter 中的会话 Trace 用例负责顺序编排两个独立查询：

1. 非 UUID 搜索词先由 Fitness 用户目录解析为匹配的用户 ID；空搜索词和 UUID 搜索词跳过此步。
2. Agent Trace 仓储根据解析后的用户 ID、UUID 搜索词、页码和每页数量查询会话。
3. Fitness 用户目录根据本页结果中的用户 ID 批量读取用户名。
4. 用例将 Agent 会话摘要与用户名组装为管理后台响应。

AgentBuilder 模块不依赖 Fitness application 或 Fitness schema；Fitness 查询 SQL 仍留在 Fitness 基础设施模块内。

## API 契约

扩展 `GET /api/admin/traces/conversations`：

- `query`：可选，去除首尾空白后最大 160 个字符。
- `page`：从 0 开始，默认 0。
- `size`：默认 10，最大 100。

搜索规则：

- 空 `query` 返回按最后活跃时间倒序排列的最近会话。
- `query` 能解析为 UUID 时，同时精确匹配 `user_id` 或 `conversation_id`。
- 其他值按用户名进行大小写不敏感的包含匹配。
- 用户名中的 `%`、`_` 按普通字符处理，不作为 SQL 通配符。
- 没有匹配项时返回空页，不返回错误。

响应由数组升级为分页对象：

- `items`：会话摘要列表。
- `page`：当前页码。
- `size`：当前每页数量。
- `hasNext`：是否存在下一页。

每个会话摘要在现有字段之外增加非空 `username`。OpenAPI、契约覆盖 fixture 和已提交的前端生成类型同步更新。

## 页面交互

页面标题下方增加一个标注为“搜索会话”的表单，输入框提示“搜索用户名、用户 ID 或会话 ID”。按回车或点击“搜索”后提交，不在每次输入时自动请求。

清空输入并提交后恢复最近会话。新的搜索条件从第 1 页开始；切换页面或刷新时保留当前搜索条件。每次加载成功后自动选中该页第一条会话并读取详情。空页清除旧详情，展示“未找到匹配会话”。

每条列表项展示：

- 会话标题和 Agent Key。
- 用户名。
- 完整用户 ID。
- 完整会话 ID。
- 消息数、运行数和最后活跃时间。

详情头部也展示用户名、完整用户 ID 和完整会话 ID。长 ID 使用等宽字体并允许换行，不通过截断隐藏实际值。

会话列表与右侧详情使用相同的可视高度。列表项区域内部滚动，分页操作固定在列表底部。分页只提供“上一页 / 第 N 页 / 下一页”：第 1 页禁用上一页，`hasNext=false` 时禁用下一页。

## 状态与错误处理

搜索、刷新和切页共享加载状态。加载期间禁用搜索和分页按钮，避免重复请求以及旧响应覆盖新结果。请求失败时保留搜索词和当前页，显示现有管理后台错误提示，允许用户再次提交或刷新。

用户名、用户 ID 或会话 ID 无匹配都属于正常空结果。超长 `query` 使用现有 `application/problem+json` 校验错误响应。所有 SQL 使用参数绑定。

## 测试与验证

按 TDD 顺序增加以下覆盖：

- Fitness 用户目录：用户名包含匹配、大小写不敏感、`%` 和 `_` 字面量处理、批量用户名读取。
- Agent Trace 仓储：空搜索最近排序、用户 ID 精确匹配、会话 ID 精确匹配、`size + 1` 判断 `hasNext`、页码偏移和空结果。
- Starter 用例与接口：用户名解析为用户 ID、结果用户名补全、UUID 双字段匹配、分页响应、参数校验和认证边界。
- 前端：统一搜索参数、身份字段展示、首次及切页自动选中、上一页/下一页状态、清空恢复、空结果和请求失败。
- 契约：OpenAPI lint、生成类型无漂移及 coverage fixture。

实现后运行相关 Maven 单元/集成测试、`architecture-tests`、前端测试、前端 typecheck、Spotless 和契约检查。测试环境缺少 Docker 时，应明确报告未运行的 Testcontainers 测试，不得将其描述为通过。
